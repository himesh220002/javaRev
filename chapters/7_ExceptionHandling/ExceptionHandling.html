Exception Handling

Exceptions

An Exception in Java is an unwanted or unexpected event occurring during the execution of a program (i.e., at runtime) that disrupts the normal flow of instructions. Exception handling is a mechanism to handle these runtime errors so that the normal flow of the application can be maintained.

  • Checked Exceptions: Exceptions checked at compile-time (e.g., IOException, SQLException).
  • Unchecked Exceptions: Exceptions checked at runtime (e.g., NullPointerException, ArithmeticException).
  • Errors: Irrecoverable conditions (e.g., OutOfMemoryError, StackOverflowError).
public class Main {
    public static void main(String[] args) {
        int a = 5 / 0; // Throws ArithmeticException
    }
}
Error vs Exception
Feature Error Exception
Recoverability Impossible to recover (e.g., system crash). Can be caught and handled to recover gracefully.
Type Classified as Unchecked. Can be Checked or Unchecked.

try catch

The try block encloses code that might throw an exception, while the catch block is used to handle that specific exception. A single try block can be followed by multiple catch blocks.

  • The JVM executes the try block, and if an exception occurs, it jumps to the matching catch block.
  • Catch blocks must be ordered from most specific subclass to the most general superclass (e.g., ArithmeticException before Exception).
try {
    int[] arr = new int[5];
    arr[5] = 10; // Throws ArrayIndexOutOfBoundsException
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Array index is out of bounds!");
} catch (Exception e) {
    System.out.println("Some other exception occurred.");
}

final finally finalize

These three keywords in Java are used in completely different contexts but are often confused due to their similar names.

  • final: A keyword used to restrict modification (constant variables, un-overridable methods, non-inheritable classes).
  • finally: A block used along with try-catch to execute crucial code (like closing resources), regardless of whether an exception is thrown or not.
  • finalize: A method from the Object class called by the Garbage Collector before an object is destroyed.
try {
    System.out.println("Inside try");
} catch(Exception e) {
    System.out.println("Inside catch");
} finally {
    System.out.println("This will always execute");
}
Differences between final, finally, and finalize
Keyword Type Purpose
final Modifier / Keyword Applies to classes, methods, and variables to restrict modification.
finally Block Used in try-catch to ensure important code always runs.
finalize Method Called by GC to perform cleanup activities before object deletion.

throw throws

Java provides the throw and throws keywords to handle custom exception throwing and method-level exception declaration.

  • throw: Used inside a method to explicitly throw an exception object.
  • throws: Used in the method signature to declare that this method might throw specific checked exceptions, passing the responsibility to the caller.
public class Test {
    // Declaring exception using 'throws'
    static void checkAge(int age) throws ArithmeticException {
        if (age < 18) {
            // Explicitly throwing an exception using 'throw'
            throw new ArithmeticException("Access denied!");
        }
    }
}
throw vs throws
Feature throw throws
Usage Location Inside the method body. In the method signature.
Action Used to explicitly throw a single exception. Used to declare one or more exceptions a method can throw.
Instance vs Class Followed by an instance of an exception (new Exception()). Followed by exception class names separated by commas.

custom exception

Java allows you to define your own exception classes by extending the Exception class (for checked exceptions) or the RuntimeException class (for unchecked exceptions).

  • Provides meaningful, domain-specific error messages.
  • Improves code readability and debugging.
// Custom Checked Exception
class InvalidAgeException extends Exception {
    public InvalidAgeException(String message) {
        super(message);
    }
}

public class Main {
    public static void validate(int age) throws InvalidAgeException {
        if (age < 18) throw new InvalidAgeException("Not eligible to vote");
    }
}

chained exceptions

Chained Exceptions allow you to relate one exception to another. This is highly useful when one exception causes another, allowing you to trace back to the original root cause.

  • The getCause() method returns the actual underlying exception.
  • The initCause() method sets the cause of an exception.
try {
    int result = 10 / 0; // Throws ArithmeticException
} catch (ArithmeticException e) {
    // Wrapping the original exception in a new exception
    throw new RuntimeException("Calculation failed", e);
}

null pointer exception

NullPointerException (NPE) is a common unchecked exception in Java that occurs when an application attempts to use null where an object instance is required.

  • Calling the instance method of a null object.
  • Accessing or modifying the field of a null object.
  • Taking the length of a null array.
String str = null;
// This line throws a NullPointerException
System.out.println(str.length());

exception handling with method overriding

When overriding a method in a subclass, Java imposes specific rules regarding the checked exceptions the overriding method can throw.

  • If superclass method does not declare an exception: The subclass overridden method cannot declare any new checked exception, but can declare unchecked exceptions.
  • If superclass method declares an exception: The subclass overridden method can declare the same exception, its subclasses, or no exception at all, but it cannot declare parent exceptions or new, broader checked exceptions.
class Parent {
    void display() throws IOException {
        System.out.println("Parent display");
    }
}

class Child extends Parent {
    // Valid: Throwing subclass of IOException (FileNotFoundException)
    // Invalid: Throwing Exception (broader than IOException)
    @Override
    void display() throws FileNotFoundException {
        System.out.println("Child display");
    }
}
