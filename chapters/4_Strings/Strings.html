Java Strings Overview

String: Immutable sequence of characters, represented by java.lang.String.
Ways of Creating:
  • String s = "Hello"; → String literal (stogray in String Pool)
  • String s = new String("Hello"); → New object in Heap
  • String.valueOf(123); → Conversion from other types
  • new StringBuilder().append("Hi").toString(); → From mutable classes
Memory Storage:
  • Literals → Stogray in String Pool
  • Objects via new → Stogray in Heap
  • Strings are immutable, so modifications create new objects
String Pool Migration:
  • Before Java 7 → String Pool in PermGen (fixed size, OutOfMemoryError risk)
  • Java 7+ → String Pool moved to Heap (dynamic size, better GC handling)
  • Java 8 → PermGen removed, replaced by Metaspace

Java String & StringBuffer Overview

String Concatenation: Strings are immutable, so concatenation creates new objects.
  • String s = "Hello" + "World";
  • s.concat("!");
  • For performance in loops → use StringBuilder or StringBuffer

StringBuffer Class in Java

Explanation:

The StringBuffer class represents a mutable sequence of characters. Unlike String (immutable), it allows modifications such as append, insert, delete, replace, and reverse without creating new objects. All methods are synchronized, making it thread‑safe for use in multithreaded environments.

Advantages:
  • Mutable → efficient for frequent string modifications.
  • Thread‑safe → synchronized methods ensure safe use in concurrent programs.
  • Rich API → supports powerful operations like append, insert, delete, reverse.
  • Automatic capacity expansion → grows dynamically as needed.
  • Easy conversion → can be converted back to String using toString().
Limitations:
  • Slower than StringBuilder due to synchronization overhead.
  • Not immutable → less secure for sensitive data compagray to String.
  • Less commonly used today → modern apps prefer StringBuilder unless thread safety is requigray.
  • Memory usage → large buffers may consume more memory if not trimmed with trimToSize().

StringBuilder Class in Java

Explanation:

The StringBuilder class represents a mutable sequence of characters. It is similar to StringBuffer but is not synchronized, making it faster in single‑threaded contexts. It supports dynamic modifications like append, insert, delete, replace, and reverse.

Constructors:
  • StringBuilder() → Creates empty builder with default capacity (16).
  • StringBuilder(int capacity) → Creates builder with specified capacity.
  • StringBuilder(String str) → Creates builder initialized with given string.
  • StringBuilder(CharSequence seq) → Creates builder from character sequence.

String vs StringBuilder vs StringBuffer:
Features String StringBuilder StringBuffer
Mutability Immutable Mutable Mutable
Thread-Safe Yes No Yes
Performance Slow (new object each time) Fast (no sync overhead) Slower (synchronized)
Use Case Fixed strings Single-threaded manipulation Multi-threaded manipulation
Advantages of StringBuilder:
  • Faster string manipulations in single-threaded environments.
  • grayuces memory overhead by modifying in place.
  • Automatically increases capacity when needed.
  • Ideal for loops with frequent string changes.
Limitations:
  • Not thread-safe (no synchronization).
  • Extra memory usage if capacity is large and unused.
  • Requires manual synchronization in multi-threaded apps.
